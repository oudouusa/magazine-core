# magazine-core 1.0.0 release notes

magazine-core 1.0.0 is the first stable release of the generic publication
metadata ingestion core. It keeps the beta wire and storage contracts stable:

```text
protocol_version = 1
record_schema_version = 1
Python SDK root plugin-author API = docs/python-sdk.md stable root API
canonical SQLite schema = 0001 core schema, no 1.0 DDL change
```

There are no protocol, SDK root API, canonical schema, or conformance fixture
changes from `0.1.0-beta.3`. The delta from `0.1.0-beta.3` is release
stabilization: package metadata, changelog, release notes, and eligibility-gate
evidence for the stable tag.

## Stable surfaces

Stable `1.x` surfaces are governed by `docs/compatibility-policy.md`:

- protocol v1 framing, JSON-RPC methods, limits, `SourceRecord`, typed
  `state_query`, `host_fetch`, cancellation, and pinned conformance fixtures;
- canonical SQLite schema and migration behavior for core databases;
- Python SDK root plugin-author API documented in `docs/python-sdk.md`;
- documented standalone quickstart and local `mh ui` browse / guarded
  management smoke for packaged UI-capable artifacts;
- GitHub Release artifact set: host binary tarball, Python SDK wheel, SBOM,
  `SHA256SUMS.txt`, and release notes.

## Verification

This release-prep commit is expected to pass:

```bash
python3 scripts/check-version-discipline.py --root . --release-ref 1.0.0 --json
bash scripts/test-version-discipline.sh
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
.venv/bin/python -m pytest sdk/python/tests
bash conformance/check_golden.sh
```

S4 release execution must then create the tag and GitHub Release at the exact
release-prep commit SHA and run:

```bash
EXPECTED_RELEASE_REF=1.0.0 RELEASE_REF_NAME=1.0.0 bash scripts/release-hardening.sh
```

For public artifact verification after assets are uploaded:

```bash
RELEASE_TAG=1.0.0 VERIFY_UI=1 bash scripts/verify-standalone-quickstart.sh
```

## Install

Use the prebuilt Linux binary from the GitHub Release:

```bash
tar -xzf magazine-core-mh-linux-x86_64.tar.gz
./mh --help
```

Install the Python SDK from the canonical wheel attached to the Release:

```bash
pip install magazine_core_plugin_sdk-1.0.0-py3-none-any.whl
```

Quickstart:

```bash
mh init-db ./scratch.db
mh inspect ./scratch.db
mh discover ./scratch.db ./plugins.d example --max-pages 1 --per-page 30 --max-records 30
```

For a self-contained artifact-only quickstart that creates the synthetic plugin
and manifest outside the source checkout, see `docs/standalone-quickstart.md`.

## Known limitations

- Prebuilt host binaries currently cover linux-x86_64 for release-consuming UI
  smoke. Other platforms can build from source.
- The bundled UI is a local tool that binds to `127.0.0.1`; it is not a remote
  management API and must not be exposed through a public interface, tunnel, or
  reverse proxy.
- Plugins are trusted executable code. The host isolates lifecycle and crashes,
  but it is not a sandbox.
