# magazine-core 0.1.0-beta.3 release notes

magazine-core 0.1.0-beta.3 is a public beta release-prep slice for proving a
UI-bearing public beta artifact. Its purpose is to unblock the
release-consuming standalone quickstart plus local UI smoke evidence required
to close the unmet `1.0.0` Eligibility Gate item for a public artifact that
contains the UI path.

This release keeps `protocol_version = 1`, `record_schema_version = 1`, the
Python SDK stable root API, and the canonical SQLite schema unchanged.

## What changed

- **Local admin/viewer UI** - `mh ui` serves a loopback-only local web UI for
  read-only DB inspection, including summary counts, source records, typed
  state, and redacted plugin manifests.
- **Explicit management mode** - `mh ui --manage` adds token-protected local
  management for bounded `init-db`, guarded `discover`, single active
  UI-started run tracking, and cancellation, with method, origin, host, and
  bounds checks.
- **UI release artifact smoke** - release hardening now forces the
  artifact-only quickstart to verify UI-capable Linux artifacts, including
  read-only browse and guarded management discover. Historical pre-UI tags
  still auto-skip UI smoke.
- **Standalone cold-start gate** - release-tag hardening dispatches publish the
  Linux assets to an existing GitHub Release and then verify the public Release
  URL with the standalone quickstart checker.
- **Version discipline** - Cargo package versions, Python SDK project metadata
  after PEP 440 normalization, release tag, `CHANGELOG.md`, and
  `docs/release/<tag>.md` must agree for version-tag hardening.
- **1.0 stabilization docs** - the public `1.0.0` eligibility gate,
  post-`1.0.0` compatibility policy, and current no-stable-tag decision are
  documented.

## Install

Use the prebuilt Linux binary from the GitHub Release:

```bash
tar -xzf magazine-core-mh-linux-x86_64.tar.gz
./mh --help
```

Install the Python SDK from the canonical wheel attached to the Release:

```bash
pip install magazine_core_plugin_sdk-0.1.0b3-py3-none-any.whl
```

Quickstart:

```bash
mh init-db ./scratch.db
mh inspect ./scratch.db
mh discover ./scratch.db ./plugins.d example --max-pages 1 --per-page 30 --max-records 30
```

For a self-contained artifact-only quickstart that creates the synthetic plugin
and manifest outside the source checkout, see `docs/standalone-quickstart.md`.

For UI-capable artifacts, the quickstart checker also verifies local
read-only UI browse and guarded `--manage` discover:

```bash
RELEASE_TAG=0.1.0-beta.3 VERIFY_UI=1 bash scripts/verify-standalone-quickstart.sh
```

## Verification

This release-prep commit is expected to pass:

```bash
python3 scripts/check-version-discipline.py --root . --release-ref 0.1.0-beta.3 --json
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
.venv/bin/python -m pytest sdk/python/tests
bash conformance/check_golden.sh
EXPECTED_RELEASE_REF=0.1.0-beta.3 RELEASE_REF_NAME=0.1.0-beta.3 bash scripts/release-hardening.sh
```

The GitHub Release assets include `SHA256SUMS.txt`; verify downloaded assets
with:

```bash
sha256sum -c SHA256SUMS.txt
```

## Known limitations

- Prebuilt host binaries currently cover linux-x86_64 for release-consuming UI
  smoke. Other platforms can build from source.
- The Python SDK wheel uses the PEP 440 version `0.1.0b3`; the Cargo packages
  and GitHub Release tag use `0.1.0-beta.3`.
- The bundled UI is a local tool that binds to `127.0.0.1`; it is not a remote
  management API and must not be exposed through a public interface, tunnel, or
  reverse proxy.
- Plugins are trusted executable code. The host isolates lifecycle and crashes,
  but it is not a sandbox.
