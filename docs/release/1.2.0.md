# magazine-core 1.2.0 release notes

magazine-core 1.2.0 is an additive minor release for the stable `1.x` line.
It adds a separately invoked trusted UI extension host while keeping every
stable data and plugin contract unchanged:

```text
protocol_version = 1
record_schema_version = 1
Python SDK root plugin-author API = unchanged
canonical SQLite schema = unchanged
```

## Trusted UI extension host

The release adds `mh-ui-ext`, an explicit opt-in binary. It validates a core
database read-only, binds shell and asset listeners only to `127.0.0.1`, serves
trusted extension assets on a separate origin, and brokers exactly two bounded
read operations (`gallery.list` and `graph.detail`) to an operator-started
provider over an owner-only Unix socket.

Trusted extension JavaScript is local executable code. The iframe sandbox,
CSP, separate origin, and fixed broker reduce accidental authority but are not
a network sandbox. `mh-ui-ext` never starts a provider and exposes no management
or write route.

## Release artifact

The existing `magazine-core-mh-linux-x86_64.tar.gz` now contains both `mh` and
`mh-ui-ext`. The package is represented in the CycloneDX SBOM and dependency
inventory with both binary names and remains covered by `SHA256SUMS.txt`.

Release hardening extracts the package, requires both executables, and runs the
real-Chrome gallery-to-graph gate with those extracted binaries. The standalone
checker retains `VERIFY_TRUSTED_UI=auto` so historical artifacts remain
verifiable; the 1.2.0 release gate uses `VERIFY_TRUSTED_UI=1`.

## Browser regression

CI builds both binaries and runs a real-Chrome test in which one sandboxed
iframe receives a gallery response and then requests graph detail using the
returned opaque Work key. The gate also verifies the dual-origin asset CSP,
absence of management routes, fixed provider contract, and browser process-tree
cleanup.

## Verification

The release commit must pass:

```bash
python3 scripts/check-version-discipline.py --root . --release-ref 1.2.0 --json
bash scripts/test-version-discipline.sh
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo test --workspace --locked
bash conformance/check_golden.sh
EXPECTED_RELEASE_REF=1.2.0 RELEASE_REF_NAME=1.2.0 bash scripts/release-hardening.sh
```

Release execution uses the exact merged commit reachable from `origin/main`:

```bash
DRY_RUN=1 bash scripts/cut-release.sh 1.2.0 <release-commit-sha>
bash scripts/cut-release.sh 1.2.0 <release-commit-sha>
```

After assets are published, the release-consuming check is:

```bash
RELEASE_TAG=1.2.0 VERIFY_UI=1 VERIFY_TRUSTED_UI=1 \
  bash scripts/verify-standalone-quickstart.sh
```

## Install

```bash
tar -xzf magazine-core-mh-linux-x86_64.tar.gz
./mh --help
./mh-ui-ext --help
pip install magazine_core_plugin_sdk-1.2.0-py3-none-any.whl
```

Prebuilt binaries remain linux-x86_64. The trusted UI host remains a local,
operator-owned tool and must not be exposed through a public tunnel or reverse
proxy.
