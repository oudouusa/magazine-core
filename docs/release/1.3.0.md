# magazine-core 1.3.0 release notes

magazine-core 1.3.0 adds an optional `env_from` list to the trusted plugin
command manifest. A one-shot host can now copy only explicitly named parent
environment values into the plugin child without storing those values in the
manifest. This closes a generic integration gap demonstrated by an
artifact-only downstream synthetic test.

The boundary remains narrow: invalid names, case-insensitive duplicates, and
overlap with literal `env` are rejected during manifest discovery. Missing or
non-UTF-8 optional values are skipped. Variables absent from `env_from` remain
unavailable after `env_clear`. Read-only manifest inspection does not resolve
values, and `PluginDefinition` debug output shows at most redacted names and
never values. The public Rust `PluginDefinition` shape remains unchanged.

Existing command manifests remain compatible. The stable contracts are
unchanged:

```text
protocol_version = 1
record_schema_version = 1
Python SDK root plugin-author API = unchanged
canonical SQLite schema = unchanged
```

Release hardening must pass on Ubuntu and macOS before publishing Linux assets,
then the public artifact-only quickstart and real-Chrome trusted UI gate must
pass against the GitHub Release URL.

```bash
python3 scripts/check-version-discipline.py --root . --release-ref 1.3.0 --json
EXPECTED_RELEASE_REF=1.3.0 RELEASE_REF_NAME=1.3.0 bash scripts/release-hardening.sh
DRY_RUN=1 bash scripts/cut-release.sh 1.3.0 <release-commit-sha>
bash scripts/cut-release.sh 1.3.0 <release-commit-sha>
RELEASE_TAG=1.3.0 VERIFY_UI=1 VERIFY_TRUSTED_UI=1 \
  bash scripts/verify-standalone-quickstart.sh
```
